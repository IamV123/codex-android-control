## v0.1.5 真机验收

1. 勾选一个应用，保持手机解锁；确认读屏、点击、输入和滚动无需逐次批准。
2. 切换到未勾选应用，确认读屏、节点操作、返回和桌面动作均拒绝；打开已勾选应用仍可执行。
3. 点击和翻页默认产生触摸，不依赖应用的控件点击或滚动实现。大众点评选择底部店铺的可见标题点按，核对实际进入详情；小红书三次上滑后打开底部内容及评论。快手触摸滑动须核对作者或内容变化，不能只根据手势回执计数。
4. 点击目标本身被替换、窗口切换或节点已失效时，要求重新读屏。
5. 锁屏、取消勾选、停止、电脑撤销或到期后应终止控制。
6. 网络中断导致结果未知时，检查实际手机状态；不自动重放。

本地回归不覆盖 Android 实际窗口与 AccessibilityNodeInfo 的厂商差异。五个短视频的停留时间与天猫超市商品选择，需要在真机任务执行后单独报告。

## v0.1.4 电脑端复制按钮修复记录

本地复现：同一码成功连接后，用新的加密 nonce 从序号 1 重新开始，被防重放校验拒绝（HTTP 400）。新复制按钮创建新会话后，第一个手机请求从序号 1 正常连接。旧浏览器页面会从服务器取得当前码，剪贴板不可用时也会显示新码供手动复制。在途命令存在时，复制新码和重新配对均返回 409，原会话继续保留。

当时真机使用新码重新连接成功，四个已选应用在后续浏览中持续连接。此修复仅覆盖复制按钮；之后用户刷新扫码、添加抖音后再次收到 400，电脑记录为 pairing_reused，故不能将该修复视为完整解决。

## v0.1.6 重连验收

本地测试复用同一二维码和主密钥，刷新网页后重新本机授权，并把抖音加入应用列表。新的 client ID 派生独立传输密钥，从自己的序号 1 开始成功连接；旧连接令牌失效。重放相同握手返回 409，旧帧重放仍被拒绝；已有操作等待回执时不允许新连接取代原连接。两个旧网页能同步新二维码，过期后清除旧码。跨 Java/Node 测试覆盖 bootstrap 握手和新传输密钥。

真机验收计划：覆盖安装 v0.1.6，连接后保持同一码停止、增加或重新确认授权并再次开始；确认电脑连续收到新连接心跳。再打开已授权抖音，执行五次触摸上滑并逐次读屏核对变化，在第五次后的页面点作者头像，核对作者主页。记录实际结果，不能仅凭手势完成回执记为通过。

已观察同一码在手机停止并重新确认后建立新连接，没有再次400，原配对ID不变。抖音恰好五次触摸上滑，每次作者或内容改变；点第五次后的作者头像，核对作者主页。大众点评重新执行“附近好吃的”搜索、两次上滑及底部店铺点按，详情页店名、评价和菜单标记已核对。无购买、加购、点赞、关注、评论发布或消息发送。私人读屏追踪留在本机工作目录，不进入公开发布包。
